# Wazuh agent by Zabbix agent / Wazuh agent by Zabbix agent active

## Overview

Monitors a Wazuh agent on Linux with Zabbix agent (passive checks): daemon processes, connection status, event rates and buffer read from the wazuh-agentd state file, and the agent version.

## Requirements

Zabbix version: 7.0 and higher.

## Setup

1. Give the zabbix user read access to the state file and VERSION.json with POSIX ACLs (package acl):
"setfacl -m u:zabbix:x /var/ossec /var/ossec/var /var/ossec/var/run"
"setfacl -m u:zabbix:r /var/ossec/VERSION.json /var/ossec/var/run/wazuh-agentd.state"
"setfacl -d -m u:zabbix:r /var/ossec /var/ossec/var/run"
The default ACLs keep the access when Wazuh recreates the files. Do not add zabbix to the wazuh group: that group can write ossec.conf, and Wazuh runs the commands configured there as root.
2. Link the template to the host.
3. If the agent is installed outside /var/ossec, change {$WAZUH.AGENT.HOME}. If <client_buffer><queue_size> is changed in ossec.conf, set {$WAZUH.AGENT.BUFFER.SIZE} to the same value.

Works with Zabbix agent and Zabbix agent 2. Tested with Wazuh agent 4.14 and Zabbix 7.0.

### Macros used

|Name|Description|Default|
|----|-----------|-------|
|{$WAZUH.AGENT.HOME}|Installation directory of the Wazuh agent.|/var/ossec|
|{$WAZUH.AGENT.BUFFER.SIZE}|Size of the anti-flooding buffer (<client_buffer><queue_size>). The Wazuh default is 5000.|5000|
|{$WAZUH.AGENT.BUFFER.UTIL.MAX.WARN}|Warning threshold of the anti-flooding buffer usage, in %.|80|
|{$WAZUH.AGENT.STATE.AGE.MAX.WARN}|Maximum age of the wazuh-agentd state file.|5m|

### Items

|Name|Description|Type|Key and additional info|
|----|-----------|----|-----------------------|
|Process [wazuh-agentd]: Number of processes|Number of running wazuh-agentd processes.|Zabbix agent|proc.num[wazuh-agentd]|
|Process [wazuh-execd]: Number of processes|Number of running wazuh-execd processes.|Zabbix agent|proc.num[wazuh-execd]|
|Process [wazuh-logcollector]: Number of processes|Number of running wazuh-logcollector processes.|Zabbix agent|proc.num[wazuh-logcollector]|
|Process [wazuh-modulesd]: Number of processes|Number of running wazuh-modulesd processes.|Zabbix agent|proc.num[wazuh-modulesd]|
|Process [wazuh-syscheckd]: Number of processes|Number of running wazuh-syscheckd processes.|Zabbix agent|proc.num[wazuh-syscheckd]|
|Get state|Contents of the wazuh-agentd state file. wazuh-agentd rewrites the file every 5 seconds by default (agent.state_interval in internal_options.conf).|Zabbix agent|vfs.file.contents[{$WAZUH.AGENT.HOME}/var/run/wazuh-agentd.state]|
|State file modification time|Last modification time of the wazuh-agentd state file. A file that is no longer updated means wazuh-agentd is stopped or hung.|Zabbix agent|vfs.file.time[{$WAZUH.AGENT.HOME}/var/run/wazuh-agentd.state,modify]|
|Connection status|Connection status of the agent: connected - connection established with the manager in the last 10 seconds, disconnected - no ACK in the last 60 seconds, pending - waiting for the connection.|DEPENDENT|wazuh.agent.status|
|Last keep-alive|Time of the last keep-alive sent to the manager, in the local time of the agent host.|DEPENDENT|wazuh.agent.last_keepalive|
|Last ACK|Time of the last control message received from the manager, in the local time of the agent host.|DEPENDENT|wazuh.agent.last_ack|
|Events generated per second|Events generated by the agent modules.|DEPENDENT|wazuh.agent.events.rate|
|Messages sent per second|Messages (events and control messages) sent to the manager.|DEPENDENT|wazuh.agent.messages.sent.rate|
|Buffered events|Events waiting in the anti-flooding buffer. No value when the buffer is disabled (<client_buffer><disabled>yes</disabled>).|DEPENDENT|wazuh.agent.buffer.events|
|Version|Version of the Wazuh agent, read from VERSION.json.|Zabbix agent|vfs.file.contents[{$WAZUH.AGENT.HOME}/VERSION.json]|

### Triggers

|Name|Description|Priority|
|----|-----------|--------|
|Wazuh agent: Process wazuh-agentd is not running|wazuh-agentd is not running. Check "systemctl status wazuh-agent" and /var/ossec/logs/ossec.log on the host.|HIGH|
|Wazuh agent: Process wazuh-execd is not running|wazuh-execd is not running. Check "systemctl status wazuh-agent" and /var/ossec/logs/ossec.log on the host.|AVERAGE|
|Wazuh agent: Process wazuh-logcollector is not running|wazuh-logcollector is not running. Check "systemctl status wazuh-agent" and /var/ossec/logs/ossec.log on the host.|AVERAGE|
|Wazuh agent: Process wazuh-modulesd is not running|wazuh-modulesd is not running. Check "systemctl status wazuh-agent" and /var/ossec/logs/ossec.log on the host.|AVERAGE|
|Wazuh agent: Process wazuh-syscheckd is not running|wazuh-syscheckd is not running. Check "systemctl status wazuh-agent" and /var/ossec/logs/ossec.log on the host.|AVERAGE|
|Wazuh agent: Not connected to the manager|The agent was not connected to the manager for 5 minutes. Events are buffered on the host and dropped when the buffer is full. Check the network path to the manager (1514/TCP) and the agent key.|AVERAGE|
|Wazuh agent: State file is not updated|wazuh-agentd has not updated its state file. The daemon is hung, or the clock of the host differs from the clock of the Zabbix server.|WARNING|
|Wazuh agent: Event buffer usage is high|The anti-flooding buffer is filling up. When it is full, new events are dropped. Set {$WAZUH.AGENT.BUFFER.SIZE} to the <client_buffer><queue_size> of the agent.|WARNING|
|Wazuh agent: Version has changed|The Wazuh agent version has changed. Acknowledge to close the problem manually.|INFO|

The template "Wazuh agent by Zabbix agent active" has the same items and triggers, collected as Zabbix agent (active) checks.
